# 0.1.d.iii Ghost Density Auditor Specification

**Purpose:** Automated tool to detect and measure "ghost" naming violations in codebases.

---

## What is Ghost Density?

**Ghost Density:** Percentage of identifiers (variables, functions, files) that are semantically incomplete.

**Formula:** `(Total Ghosts / Total Identifiers) × 100`

## Ghost Patterns

### High-Severity Ghosts
- Generic function names: `handleClick`, `onClick`, `getData`, `processData`
- Generic variables: `data`, `value`, `item`, `result`, `temp`
- Generic file names: `utils.js`, `helpers.ts`, `common.js`
- Generic folder names: `components/`, `utils/`, `helpers/`

### Medium-Severity Ghosts
- Partially semantic: `handleUserClick` (which user? where?)
- Domain-less: `renderList` (list of what?)
- Context-less: `validateForm` (which form?)

### Low-Severity Ghosts
- Acceptable abbreviations in limited scope
- Test mocks with generic names
- Auto-generated identifiers

## Auditor Requirements

### Input
- Codebase directory
- Configuration: severity thresholds, exclusions

        return '';
    }

## CLI Usage

```bash
# Run audit
ghostless-audit ./src

# Run with output file
ghostless-audit ./src --output ghost-report.json

# Run with threshold enforcement (fails CI if exceeded)
ghostless-audit ./src --max-density 5 --fail-on-exceed

# Show only high-severity violations
ghostless-audit ./src --severity high

# Auto-fix (rename with suggestions)
ghostless-audit ./src --fix --interactive
```
