## 📖 THE FLAT ARCHITECTURE PROBLEM

Traditional codebases are flat:

```
src/
├── components/
│   ├── Button.tsx
│   ├── Modal.tsx
│   ├── Dashboard.tsx
│   └── PaymentForm.tsx
├── utils/
│   ├── api.ts
│   ├── validation.ts
│   └── helpers.ts
└── services/
    ├── auth.ts
    └── payments.ts
```

**Problems:**
- No indication of abstraction levels
- Authentication lives alongside UI components
- Low-level utilities mixed with high-level business logic
- No clear dependency direction
- Impossible to understand system hierarchy at a glance

**Cognitive Tier Architecture solves this through explicit vertical layering.**

---

## 1.0 WHAT ARE COGNITIVE TIERS?

**Cognitive Tiers:** Numbered abstraction layers that organize code by increasing complexity and specificity, where lower tiers provide infrastructure and higher tiers provide application logic.

### Core Principle

```
Higher tiers CAN depend on lower tiers
Lower tiers CANNOT depend on higher tiers
```

This creates a **dependency pyramid** that prevents circular dependencies and enforces clean architecture.

## 3.0 DEPENDENCY RULES

### ✅ Allowed Dependencies

```
Tier 7 (Tests) ───────────┐
Tier 6 (Experiments) ─────┤
Tier 5 (Documentation) ───┤
Tier 4 (Tools) ───────────┤
Tier 3 (Features) ────────┤
Tier 2 (Services) ────────┤
Tier 1 (Core) ────────────┤
Tier 0 (Security) ────────┘
         ↓
    Foundation
```

**Rule:** Any tier can depend on any lower-numbered tier.

### ❌ Forbidden Dependencies

```typescript
// ❌ WRONG: Tier 0 depending on Tier 1
// File: 0.0.a_fileAuthValidationCore.ts
import { intentStateEngineDashboardPrimary } from '../1.0_core/1.0.a_fileDashboardStateEngine';
// This violates tier rules!

// ✅ CORRECT: Tier 1 depending on Tier 0
// File: 1.0.a_fileDashboardStateEngine.ts
import { logger } from '../0.2_infrastructure/0.2.3.a_fileLoggerCore';
// This follows tier rules
```

## 6.0 ENFORCING TIER BOUNDARIES

### Automated Tier Validation

```typescript
// tierValidator.ts

interface TierDependency {
  file: string;
  tier: number;
  imports: { file: string; tier: number }[];
}

function validateTierBoundaries(dependencies: TierDependency[]): boolean {
  for (const dep of dependencies) {
    for (const imp of dep.imports) {
      if (imp.tier > dep.tier) {
        console.error(`❌ Tier violation: ${dep.file} (Tier ${dep.tier}) ` +
          `depends on ${imp.file} (Tier ${imp.tier})`);
        return false;
      }
    }
  }
  return true;
}
```

### ESLint Rule for Tier Enforcement

```javascript
// eslint-plugin-tier-boundaries.js

module.exports = {
  rules: {
    'no-upward-dependencies': {
      create(context) {
        return {
          ImportDeclaration(node) {
            const currentFile = context.getFilename();
            const importPath = node.source.value;

            const currentTier = extractTier(currentFile);
            const importTier = extractTier(importPath);

            if (importTier > currentTier) {
              context.report({
                node,
                message: `Tier ${currentTier} cannot depend on Tier ${importTier}`
              });
            }
          }
        };
      }
    }
  }
};

function extractTier(filePath) {
  const match = filePath.match(/\/(\d+)\.\d+_/);
  return match ? parseInt(match[1]) : 0;
}
```

// 2.1.a_filePaymentProcessing.ts

  const encrypted = crypto.encrypt(cardNumber, KEY); // ❌ Should be Tier 0

## 8.0 COGNITIVE TIER VS. TRADITIONAL LAYERING

| Aspect | Cognitive Tiers | Traditional Layers | MVC | Clean Architecture |
|--------|----------------|-------------------|-----|-------------------|
| **Visibility** | ✅ In file paths | ❌ In folder names only | ❌ By convention | ⚠️ By abstraction |
| **Enforcement** | ✅ Automated | ❌ Manual | ❌ Manual | ⚠️ Tooling required |
| **Granularity** | ✅ 10 levels (0-9) | ⚠️ 3-4 layers | ❌ 3 layers | ⚠️ 4-5 circles |
| **Semantic Clarity** | ✅ Ghostless naming | ❌ Generic | ❌ Generic | ❌ Generic |
| **Dependency Direction** | ✅ Clear (down only) | ⚠️ Implicit | ⚠️ Unclear | ✅ Clear |
| **Testability** | ✅ Tier-by-tier | ⚠️ Layer-by-layer | ❌ Complex | ✅ Good |

## 9.0 ADVANCED TIER PATTERNS

### 9.1 Cross-Tier Communication via Events

```typescript
// Tier 1: Core Event Emitter (1.0.e_fileEventBusCore.ts)
export const eventBus = {
  listeners: {},

  emit(event: string, data: any): void {
    logger.log('📢 1.0.e_fileEventBusCore: Emitting event=' + event);
    this.listeners[event]?.forEach(callback => callback(data));
  },

  on(event: string, callback: Function): void {
    if (!this.listeners[event]) {
      this.listeners[event] = [];
    }
    this.listeners[event].push(callback);
  }
};

// Tier 3: Feature listens to core events
// 3.1.a_fileContributorHandler.ts
import { eventBus } from '../1.0_core/1.0.e_fileEventBusCore'; // ✅ Tier 1

eventBus.on('dashboard:item:selected', (itemId) => {
  logger.log('🎯 3.1.a_fileContributorHandler: Dashboard item selected=' + itemId);
  // Handle at feature level
});
```
